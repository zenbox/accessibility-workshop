Die 4 Kontrastthemes in Windows 11

Unter Einstellungen → Barrierefreiheit → Kontrastdesigns bietet Windows 11 vier vordefinierte Themes an. Jedes Theme definiert Farben für Hintergrund, Text, Links, markierten Text, inaktiven Text und Schaltflächenelemente. Nutzer können die Farben individuell anpassen.

CSS System-Color-Keywords

In forced-colors: active kann der Browser nur bestimmte System-Farben verwenden. Diese Keywords sind case-insensitive und repräsentieren jeweils eine Farbrolle im System-Theme des Nutzers.

Keyword Beschreibung Typische Verwendung
Canvas Hintergrund von Dokumenten und App-Inhalten background-color des <body>
CanvasText Textfarbe in Dokumenten und App-Inhalten color auf normalen Textelementen
LinkText Farbe nicht-besuchter, nicht-aktiver Links color auf <a>-Elementen
VisitedText Farbe bereits besuchter Links a:visited { color }
ActiveText Farbe aktiver Links (während des Klicks) a:active { color }
ButtonFace Hintergrund von Schaltflächen background-color auf <button>
ButtonText Textfarbe in Schaltflächen color auf <button>
ButtonBorder Rahmen von Schaltflächen border-color auf <button>
Field Hintergrund von Eingabefeldern background-color auf <input>
FieldText Textfarbe in Eingabefeldern color auf <input>
Highlight Hintergrund markierter/selektierter Elemente ::selection { background-color }
HighlightText Text in markierten/selektierten Elementen ::selection { color }
SelectedItem Hintergrund aktiv ausgewählter Elemente (z.B. Checkbox) Aktive Auswahl in Formularen
SelectedItemText Text in aktiv ausgewählten Elementen Farbe des Häkchens in Checkbox
Mark Hintergrund für speziell markierten Text (<mark>) background-color auf <mark>
MarkText Text in speziell markiertem Bereich color auf <mark>
GrayText Inaktiver/deaktivierter Text color auf :disabled Elementen
AccentColor Akzentfarbe des Systems Benutzerdefinierte Akzentfarbe
AccentColorText Text auf Akzentfarben-Hintergrund Kontrasttext zur Akzentfarbe

Media Queries & CSS-Erkennung

Der Forced-Colors-Modus wird über standardisierte Media Queries erkannt. Die alte proprietäre -ms-high-contrast Query ist seit Edge 134 deprecated.

CSS 
/* ── Primäre Erkennung ── */
@media (forced-colors: active) {
  /* Styles für den Hochkontrastmodus */
}

@media (forced-colors: none) {
  /* Normaler Modus (Standard) */
}

/* ── Äquivalente Alternative ── */
@media (prefers-contrast: forced) {
  /* Gleiches Ergebnis wie forced-colors: active */
}

/* ── Kontrastpräferenz (nicht forced) ── */
@media (prefers-contrast: more) {
  /* Nutzer bevorzugt höheren Kontrast */
}

@media (prefers-contrast: less) {
  /* Nutzer bevorzugt geringeren Kontrast */
}

/* ── DEPRECATED: Nicht mehr verwenden ── */
@media (-ms-high-contrast: active) {
  /* Veraltet seit Edge 134 */
}
info

Hinweis: Safari unterstützt forced-colors nicht, da Apple auf prefers-contrast setzt. Zum Testen im Browser: Edge/Chrome DevTools → Rendering → Emulate CSS media feature forced-colors → active.

Vom Browser überschriebene CSS-Properties

Im Forced-Colors-Modus überschreibt der Browser bestimmte farbrelated CSS-Properties mit System-Farben oder entfernt sie. Autorenseitige Werte werden ignoriert, sofern nicht forced-color-adjust: none gesetzt ist.

CSS-Property Verhalten im Forced-Colors-Modus
color Wird auf System-Farbe gesetzt (z.B. CanvasText, ButtonText, LinkText)
background-color Wird auf System-Farbe gesetzt (z.B. Canvas, ButtonFace, Field)
border-color Wird auf System-Farbe gesetzt (z.B. ButtonText)
outline-color Wird auf System-Farbe gesetzt
text-decoration-color Wird auf System-Farbe gesetzt
column-rule-color Wird auf System-Farbe gesetzt
-webkit-tap-highlight-color Wird auf System-Farbe gesetzt
fill / stroke Wird auf System-Farbe gesetzt (SVG)
caret-color Wird auf System-Farbe gesetzt
box-shadow Wird auf none erzwungen
text-shadow Wird auf none erzwungen
background-image Wird auf none erzwungen (außer url())
color-scheme Wird auf light dark erzwungen
scrollbar-color Wird auf auto erzwungen
accent-color Wird auf auto erzwungen
CSS 
/* forced-color-adjust steuert, ob ein Element
   vom System überschrieben wird oder nicht */

.custom-widget {
  forced-color-adjust: none;
  /* Eigene Farben werden NICHT überschrieben.
     Vorsicht: Kontrast muss manuell sichergestellt werden! */
}

.standard-element {
  forced-color-adjust: auto; /* Standard */
}

Praxisbeispiele

Typische Situationen, in denen Anpassungen für den Forced-Colors-Modus nötig sind. Aktiviere in den DevTools Emulate forced-colors: active, um die Wirkung zu sehen.

smart_button Beispiel 1: Button mit box-shadow → Border-Fallback
CSS 
.btn {
  border: 0;
  padding: 10px 20px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.2);
  background: #0078d4;
  color: white;
}

@media (forced-colors: active) {
  .btn {
    /* box-shadow wird zu none — Border als Ersatz */
    border: 2px solid ButtonText;
  }
}
check_box Beispiel 2: Custom Checkbox mit CSS-Indikator
CSS 
/* Problem: background-color allein ist im
   Forced-Colors-Modus nicht sichtbar */
.checkbox-indicator {
  background-color: #0078d4; /* Wird überschrieben! */
}

/* Lösung: Border statt background verwenden */
@media (forced-colors: active) {
  .checkbox-indicator {
    border: 2px solid SelectedItem;
    forced-color-adjust: none;
  }
  input:checked + .checkbox-indicator {
    background: SelectedItem;
    color: SelectedItemText;
  }
}
link Beispiel 3: Links und States
Normaler Link Deaktivierter Text
CSS 
@media (forced-colors: active) {
  a {
    color: LinkText;
  }
  a:visited {
    color: VisitedText;
  }
  a:active {
    color: ActiveText;
  }
  .disabled {
    color: GrayText;
  }
}
draw Beispiel 4: SVG-Icons mit currentColor
SVG mit fill="currentColor" / stroke="currentColor"
CSS 
/* Best Practice: currentColor nutzen,
   dann erbt das SVG die Forced-Color-Textfarbe */
.icon {
  color: currentColor;
  fill: currentColor;
}

/* Falls nötig, explizit in forced-colors */
@media (forced-colors: active) {
  .icon {
    color: CanvasText;
    forced-color-adjust: auto;
  }
}
center_focus_strong Beispiel 5: Focus-Indikator
CSS 
/* Outline wird im Forced-Colors-Modus
   auf System-Farben gemappt — nutze das! */
:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}

@media (forced-colors: active) {
  :focus-visible {
    outline-color: Highlight;
  }
}

Best Practices

check_circle

Verwende semantisches HTML. Der Browser weist System-Farben basierend auf der Element-Semantik zu (<a> bekommt LinkText, <button> bekommt ButtonText). ARIA-Rollen werden dabei nicht berücksichtigt.

check_circle

Nutze transparent-Borders. Statt Borders nur im Forced-Colors-Modus hinzuzufügen, setze im Normalzustand border: 2px solid transparent. Im Forced-Colors-Modus wird transparent zur System-Farbe — kein Layout-Shift.

check_circle

System-Colors statt Hex-Werte. Verwende innerhalb von @media (forced-colors: active) immer System-Color-Keywords wie CanvasText, ButtonText, Highlight. Statische Hex-Werte können zu Kontrastproblemen führen.

check_circle

Setze forced-color-adjust: none sparsam ein. Dieses Property entzieht ein Element dem System-Override. Nur verwenden, wenn die eigene Farbgebung kontrastgeprüft ist (z.B. Datenvisualisierungen).

check_circle

Teste mit echten Themes. Edge/Chrome DevTools: Rendering → Emulate CSS media feature forced-colors: active. Für ein vollständiges Ergebnis zusätzlich unter Windows Einstellungen → Barrierefreiheit → Kontrastdesigns alle vier Themes testen.

CSS — Transparent-Border-Trick 
/* Normaler Zustand: unsichtbarer Border */
.card {
  border: 2px solid transparent;
  border-radius: 8px;
  background: #1a1a2e;
}

/* Forced Colors: transparent wird automatisch
   zur System-Farbe → Border wird sichtbar,
   kein Layout-Shift, kein zusätzliches CSS nötig! */
