ARIA und Landmarks

ARIA steht für Accessible Rich Internet Applications und ist eine Spezifikation des W3C, die es ermöglicht, Webseiten und Webanwendungen für Menschen mit Behinderungen, insbesondere für die Interpretation durch Screenreader zugänglicher zu machen.

ARIA enthält mehrere Hauptkomponenten:

  • Properties: Attribute, die
    1. Textinformationen hinzufügen von Elementen beschreiben.
    2. States: Eine weitere Gruppe umfasst das Verhalten bei Änderungen des DOM.
    3. Schließlich gibt es noch Relationen, die Beziehungen zwischen Elementen beschreiben.
  • Roles: Rollen, die Elementen zugewiesen werden können, um die semantische Bedeutung eines Elements zu erzeugen oder zu ändern.

Die folgenden Beispiele sind nicht vollständig. Eine vollständige Beschreibung aller ARIA-Attribute gibt es zum Beispiel bei SELFHTML.

ARIA-Attribute, die Textinformationen für Screenreader hinzufügen

Die folgenden Attribute können Textinformationen für Screenreader hinzufügen:

aria-label

<button aria-label="Schließen" class="fa fa-close"></button>

Ein Label, das den Inhalt eines Elements beschreibt, hier eine Schaltfläche mit einem Schliessen-Icon. Es wird von Screenreadern vorgelesen, wenn das Element fokussiert ist.

aria-labelledby

<span
    class="visually-hidden"
    id="dialog-title"
>
    Fenster schließen
</span>
<button
    type="button"
    aria-labelledby="dialog-title"
>
    ×
</button>

Die ID eines anderen Elements, dessen Inhalt als Label für das aktuelle Element verwendet wird.

aria-describedby

<p
    class="visually-hidden" 
    id="close-help"
>
    Schließt das Fenster.
</p>
<button
    type="button"
    aria-describedby="close-help"
>
    Schließen
</button>

Die ID eines anderen Elements, dessen Inhalt als Beschreibung für das aktuelle Element verwendet wird.

ARIA-Attribute, die den Zustand von Elementen beschreiben

Die folgenden Attribute können den Zustand von Elementen beschreiben:

aria-disabled

Gibt an, ob ein Element deaktiviert ist.<div role="button" aria-disabled="true" tabindex="0">Speichern</div>

aria-hidden

Gibt an, ob ein Element für Screenreader sichtbar ist.<div aria-hidden="true">

aria-checked

Gibt an, ob ein Element ausgewählt ist.<div role="checkbox" aria-checked="true" tabindex="0">Newsletter</div>

aria-pressed

Gibt an, ob ein Element gedrückt ist.<button aria-pressed="true">

aria-expanded

Gibt an, ob ein Element erweitert ist.<button aria-expanded="true" aria-controls="details" type="button">Details</button> <div id="details">…</div>

aria-selected

Gibt an, ob ein Element innerhalb eines Auswahl-Widgets ausgewählt ist (z.B. in listbox, tabs).<div role="tablist" aria-label="Ansichten">   <button role="tab" aria-selected="true" aria-controls="panel-a" id="tab-a" type="button">Übersicht</button>   <button role="tab" aria-selected="false" aria-controls="panel-b" id="tab-b" type="button">Details</button> </div> <section role="tabpanel" id="panel-a" aria-labelledby="tab-a">…</section> <section role="tabpanel" id="panel-b" aria-labelledby="tab-b" hidden>…</section>

aria-current

Markiert das „aktuelle“ Element in einer Menge verwandter Elemente (z.B. aktuelle Seite, aktueller Schritt).<nav aria-label="Brotkrumen">   <ol>     <li><a href="/">Start</a></li>     <li><a href="/konto" aria-current="page">Konto</a></li>   </ol> </nav>

aria-required

Kennzeichnet ein Eingabefeld als erforderlich. (Hinweis: In HTML ist required oft die bessere Wahl.)<label for="email">E‑Mail</label> <input id="email" name="email" type="email" aria-required="true" autocomplete="email">

aria-invalid

Markiert ein Feld als ungültig.<label for="zip">PLZ</label> <input id="zip" name="zip" inputmode="numeric" aria-invalid="true" aria-describedby="zip-error"> <p id="zip-error" class="error">Bitte eine gültige PLZ eingeben.</p>

aria-errormessage

Verknüpft ein ungültiges Feld mit einem Element, das die Fehlermeldung enthält. Wird typischerweise zusammen mit aria-invalid="true" eingesetzt.<label for="password">Passwort</label> <input id="password" name="password" type="password" aria-invalid="true" aria-errormessage="pw-error"> <p id="pw-error" class="error">Mindestens 12 Zeichen.</p>

aria-modal

Kennzeichnet einen Dialog als modal, d.h. der Fokus bleibt im Dialog, bis er geschlossen wird.<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">…</div>

und so weiter.

ARIA-Attribute, die beobachten, ob es am DOM Veränderungen gibt:

Die folgenden Attribute können beobachten, ob es am DOM Veränderungen gibt:

aria-atomic

Gibt an, ob ein Element atomar ist, d.h. ob es als Ganzes gelesen werden soll.<div role="alert" aria-atomic="true"> <p>Wichtige Nachricht:</p> <p>Ihr Profil wurde erfolgreich aktualisiert.</p> </div>

aria-busy

Gibt an, ob ein Element gerade beschäftigt ist.<section aria-busy="true" aria-label="Suchergebnisse">…</section>

aria-live

Gibt an, ob Änderungen an einem Element sofort vorgelesen werden sollen.

aria-live: Änderungen ankündigen

aria-live eignet sich für Inhalte, die sich dynamisch ändern, ohne dass der Fokus dorthin verschoben wird. Screenreader können die Änderung automatisch vorlesen.

Beispiel 1: Erfolgreiches Speichern

Wichtig: Die Live-Region sollte bereits im HTML existieren. Nur ihr Inhalt wird später geändert.

<button type="button" id="save-button">
    Speichern
</button>

<p
    id="save-status"
    class="status-message"
    aria-live="polite"
    aria-atomic="true"
></p>

<script>
    const saveButton = document.querySelector('#save-button');
    const saveStatus = document.querySelector('#save-status');

    saveButton.addEventListener('click', () => {
        saveStatus.textContent = 'Änderungen wurden gespeichert.';
    });
</script>

Warum diese Attribute?

aria-live="polite": Die Meldung wird vorgelesen, sobald der Screenreader einen passenden Moment erreicht.

aria-atomic="true": Die gesamte Meldung wird vorgelesen, nicht nur ein einzelnes geändertes Wort.

Für wichtige, sofortige Meldungen kann aria-live="assertive" verwendet werden:

<p id="connection-status" aria-live="assertive"></p>

<script>
    document.querySelector('#connection-status').textContent =
        'Die Verbindung zum Server wurde unterbrochen.';
</script>

assertive sollte sparsam eingesetzt werden, da die aktuelle Sprachausgabe unterbrochen werden kann.

Beispiel 2: Warenkorb aktualisieren

<button type="button" id="add-to-cart">
    In den Warenkorb
</button>

<span id="cart-count" aria-hidden="true">0</span>

<p id="cart-status" class="visually-hidden" aria-live="polite"></p>

<script>
    let cartItems = 0;

    document.querySelector('#add-to-cart').addEventListener('click', () => {
        cartItems += 1;

        document.querySelector('#cart-count').textContent = cartItems;
        document.querySelector('#cart-status').textContent =
            Produkt wurde hinzugefügt. ${cartItems} Produkte im Warenkorb.;
    });
</script>

Das sichtbare Zählfeld ist für die visuelle Orientierung zuständig. Die Live-Region liefert zusätzlich eine verständliche Ansage für Screenreader.

Beispiel 3: Suchergebnisse

<label for="search">Seminar suchen</label>
<input type="search" id="search">

<p id="search-status" aria-live="polite" aria-atomic="true"></p>

<ul id="results"></ul>

<script>
    const searchInput = document.querySelector('#search');
    const searchStatus = document.querySelector('#search-status');
    const results = document.querySelector('#results');

    searchInput.addEventListener('input', () => {
        const query = searchInput.value.trim();

        if (query === '') {
            results.innerHTML = '';
            searchStatus.textContent = '';
            return;
        }

        const resultCount = 3;

        results.innerHTML = 
            <li>JavaScript Grundlagen</li>
            <li>JavaScript für Fortgeschrittene</li>
            <li>Web Accessibility mit JavaScript</li>
        ;

        searchStatus.textContent =
            ${resultCount} Ergebnisse für ${query}.;
    });
</script>

aria-errormessage: Fehlermeldungen zuordnen

aria-errormessage verbindet ein Eingabefeld mit der konkreten Fehlermeldung.

Voraussetzungen:

Das Eingabefeld hat aria-invalid="true".

aria-errormessage enthält die ID der Fehlermeldung.

Die Fehlermeldung ist im DOM vorhanden und sichtbar oder zugänglich.

Der Text beschreibt konkret, wie der Fehler behoben werden kann.

Beispiel 1: E-Mail-Adresse validieren

<form id="registration-form" novalidate>
    <div>
        <label for="email">E-Mail-Adresse</label>

        <input
            type="email"
            id="email"
            name="email"
            aria-invalid="false"
            aria-errormessage="email-error"

        <p id="email-error" class="error-message" hidden>
            Bitte geben Sie eine gültige E-Mail-Adresse ein,
            zum Beispiel name@beispiel.de.
        </p>
    </div>

    <button type="submit">Registrieren</button>
</form>

<script>
    const form = document.querySelector('#registration-form');
    const email = document.querySelector('#email');
    const emailError = document.querySelector('#email-error');

    form.addEventListener('submit', (event) => {
        event.preventDefault();

        const isValid = email.validity.valid && email.value.trim() !== '';

        email.setAttribute('aria-invalid', String(!isValid));
        emailError.hidden = isValid;

        if (!isValid) {
            email.focus();
        }
    });
</script>

Wenn die Eingabe ungültig ist, entsteht sinngemäß folgende Beziehung:

<input
    id="email"
    aria-invalid="true"
    aria-errormessage="email-error"

<p id="email-error">
    Bitte geben Sie eine gültige E-Mail-Adresse ein.
</p>

Beispiel 2: Passwortregeln und Fehlermeldung unterscheiden

Für allgemeine Hinweise ist aria-describedby passend. Für einen konkreten Validierungsfehler wird aria-errormessage verwendet.

<label for="password">Passwort</label>

<input
    type="password"
    id="password"
    aria-describedby="password-hint"
    aria-invalid="false"
    aria-errormessage="password-error"

<p id="password-hint">
    Mindestens 12 Zeichen, ein Großbuchstabe und eine Zahl.
</p>

<p id="password-error" class="error-message" hidden>
    Das Passwort erfüllt noch nicht alle Anforderungen.
</p>


<script>
const password = document.querySelector('#password');
const passwordError = document.querySelector('#password-error');

password.addEventListener('blur', () => {
    const value = password.value;

    const isValid =
        value.length >= 12 &&
        /[A-Z]/.test(value) &&
        /\d/.test(value);

    password.setAttribute('aria-invalid', String(!isValid));
    passwordError.hidden = isValid;
});
</script>

Beispiel 3: Mehrere Felder in einem Formular

<form id="booking-form" novalidate>
    <div>
        <label for="first-name">Vorname</label>
        <input
            id="first-name"
            name="first-name"
            aria-invalid="false"
            aria-errormessage="first-name-error"
        <p id="first-name-error" class="error-message" hidden>
            Bitte geben Sie Ihren Vornamen ein.
        </p>
    </div>

    <div>
        <label for="participants">Anzahl der Teilnehmenden</label>
        <input
            id="participants"
            name="participants"
            type="number"
            min="1"
            aria-invalid="false"
            aria-errormessage="participants-error"
        <p id="participants-error" class="error-message" hidden>
            Bitte geben Sie mindestens eine teilnehmende Person an.
        </p>
    </div>

    <button type="submit">Anfrage senden</button>
</form>

<script>
    const bookingForm = document.querySelector('#booking-form');

    bookingForm.addEventListener('submit', (event) => {
        event.preventDefault();

        const firstName = document.querySelector('#first-name');
        const participants = document.querySelector('#participants');

        const fields = [
            {
                input: firstName,
                error: document.querySelector('#first-name-error'),
                valid: firstName.value.trim() !== ''
            },
            {
                input: participants,
                error: document.querySelector('#participants-error'),
                valid: Number(participants.value) >= 1
            }
        ];

        let firstInvalidField = null;

        fields.forEach(({ input, error, valid }) => {
            input.setAttribute('aria-invalid', String(!valid));
            error.hidden = valid;

            if (!valid && !firstInvalidField) {
                firstInvalidField = input;
            }
        });

        if (firstInvalidField) {
            firstInvalidField.focus();
        }
    });
</script>

aria-live und aria-errormessage gemeinsam verwenden

Bei einer Formularprüfung kann eine zusätzliche Live-Region die Anzahl der Fehler ankündigen:

<div
    id="form-status"
    role="status"
    aria-live="polite"
    aria-atomic="true"
></div>

<script>
const invalidFields = fields.filter(field => !field.valid);

document.querySelector('#form-status').textContent =
    invalidFields.length === 0
        ? 'Formular wurde erfolgreich gesendet.'
        : ${invalidFields.length} Eingabefelder enthalten Fehler.;
</script>

role="status" entspricht in diesem Fall im Wesentlichen einer höflichen Live-Region. Verwende nicht zusätzlich unnötig role="alert" am gesamten Formular.

Häufige Fehler

Fehlermeldung ohne aria-invalid

<!-- Ungünstig -->
<input aria-errormessage="email-error">

Besser:

<input
    aria-invalid="true"
    aria-errormessage="email-error"

Fehlermeldung mit falscher ID

<input
    aria-invalid="true"
    aria-errormessage="wrong-id"

<p id="email-error">Ungültige E-Mail-Adresse.</p>

Die ID muss exakt übereinstimmen:

<input
    aria-invalid="true"
    aria-errormessage="email-error"

<p id="email-error">Ungültige E-Mail-Adresse.</p>

Jede kleine Änderung als assertive ankündigen

<!-- Zu aggressiv für normale Statusänderungen -->
<div aria-live="assertive">
    Zeichen eingegeben
</div>

Für Suchergebnisse, Speichervorgänge oder Warenkorbänderungen ist meistens besser:

<div aria-live="polite"></div>

Inhalt der Live-Region ständig ersetzen

Ungünstig:

status.innerHTML = 
    <h2>Erfolg</h2>
    <p>Die Daten wurden gespeichert.</p>
;

Besser für eine kurze Statusmeldung:

status.textContent = 'Die Daten wurden gespeichert.';

Merksatz

aria-live: „Bitte kündige diese dynamische Änderung an.“

aria-errormessage: „Diese konkrete Fehlermeldung gehört zu diesem ungültigen Eingabefeld.“

aria-describedby: „Diese zusätzliche Beschreibung oder Anleitung gehört zu diesem Element.“

<output
    role="status"
    aria-live="polite"
    aria-atomic="true"
>
    0 Treffer
</output>

<label for="">
    Name
</label>
<input
    type="text"
    id="my-name"
/>
<p
    aria-live="assertive"
></p>

aria-relevant

Gibt an, welche Art von Änderungen an einem Element vorgelesen werden sollen.

<div role="status" aria-live="polite" aria-relevant="additions">     …   </div>

ARIA-Attribute, die ein Verhalten von Elementen beschreiben

Die folgenden Attribute können Verhalten/Beziehungen von Elementen beschreiben:

aria-haspopup

Gibt an, ob ein Element ein Popup (z.B. menu, listbox oder dialog) öffnet.<button aria-haspopup="menu" aria-expanded="false" aria-controls="user-menu" type="button">Profil</button> <div id="user-menu" role="menu">…</div>

aria-owns

Die ID eines anderen Elements, das von diesem Element besessen wird.<div role="listbox" aria-owns="opt-1 opt-2">…</div> <div id="opt-1" role="option">Option 1</div> <div id="opt-2" role="option">Option 2</div>

aria-controls

Die ID eines anderen Elements, das von diesem Element kontrolliert wird.<button aria-controls="filters" aria-expanded="false" type="button">Filter</button> <section id="filters">…</section>

aria-flowto

Die ID eines anderen Elements, das von diesem Element fokussiert wird.<p id="step-1" aria-flowto="step-2">Schritt 1…</p> <p id="step-2">Schritt 2…</p>

aria-activedescendant

Die ID eines anderen Elements, das von diesem Element aktiviert wird.<div role="listbox" tabindex="0" aria-activedescendant="opt-2">…</div> <div id="opt-1" role="option">Option 1</div> <div id="opt-2" role="option" aria-selected="true">Option 2</div>

aria-valuenow

Der aktuelle numerische Wert eines Widgets (z.B. slider).<div role="slider" tabindex="0" aria-label="Lautstärke" aria-valuemin="0" aria-valuemax="100" aria-valuenow="30">…</div>

aria-valuemin, aria-valuemax

Untere und obere Grenze eines numerischen Widgets.<div role="spinbutton" tabindex="0" aria-label="Anzahl" aria-valuemin="1" aria-valuemax="10" aria-valuenow="1">1</div>

aria-valuetext

Textuelle Beschreibung des aktuellen Werts (wenn aria-valuenow alleine nicht ausreicht).<div role="slider" tabindex="0" aria-label="Zoom" aria-valuemin="0" aria-valuemax="4" aria-valuenow="2" aria-valuetext="200%">…</div>

und so weiter.

Landmarks (roles)

Landmarks sind semantische Rollen, die es Screenreadern ermöglichen, die Struktur einer Webseite zu erkennen. Sie können nicht-semantischen div-Elemente eine semantische Bedeutung geben. Sie können auch die Semantik eines HTML-Elements ändern.

In HTML gilt: Wenn ein passendes semantisches Element existiert (<header>, <nav>, <main>, <aside>, <footer>), ist das meistens die bessere Wahl als ein zusätzliches role auf einem <div>.

Wenn es mehrere Bereiche mit derselben Landmark-Rolle gibt (z.B. mehrere Navigationsbereiche), sollten sie eindeutig benannt werden (z.B. mit aria-label oder aria-labelledby), damit Screenreader sie gut unterscheiden können.

role="banner"

Ein Bereich, der den Kopf einer Webseite enthält. Er kann mehrere Elemente enthalten, wie z.B. ein Logo, eine Überschrift, eine Suchfunktion und eine Navigation.<header role="banner">…</header>

role="navigation"

Ein Bereich, der eine Navigation enthält. Er kann mehrere Elemente enthalten, wie z.B. eine Liste von Links oder eine Suchfunktion.<nav aria-label="Hauptnavigation">…</nav>

role="main"

Der Hauptinhalt einer Webseite. Er kann mehrere Elemente enthalten, wie z.B. Artikel, Abschnitte und Nebeninhalte.<main>…</main>

role="complementary"

Ein Bereich, der zusätzliche Informationen enthält, die nicht zum Hauptinhalt gehören. Er kann mehrere Elemente enthalten, wie z.B. eine Sidebar, eine Werbung oder verwandte Links.<aside aria-label="Weiterführende Links">…</aside>

role="contentinfo"

Ein Bereich, der Informationen über die Webseite enthält. Er kann mehrere Elemente enthalten, wie z.B. ein Impressum, eine Datenschutzerklärung und eine Kontaktadresse.<footer>…</footer>

role="search"

Ein Bereich, der eine Suchfunktion enthält. Er kann mehrere Elemente enthalten, wie z.B. ein Eingabefeld, eine Schaltfläche und eine Ergebnisliste.<form role="search" aria-label="Website durchsuchen">…</form>

role="form"

Ein Bereich, der ein Formular enthält. Er kann mehrere Elemente enthalten, wie z.B. Eingabefelder, Schaltflächen und Auswahllisten.<form role="form" aria-labelledby="contact-title">…</form>

role="region"

Ein wichtiger Abschnitt der Seite, der als Landmark auftauchen soll. Regionen sollten immer benannt werden (z.B. per aria-label), sonst ist der Landmark-Eintrag für Nutzer:innen wenig hilfreich.<section role="region" aria-label="Aktuelle Hinweise">…</section>

und so weiter.
